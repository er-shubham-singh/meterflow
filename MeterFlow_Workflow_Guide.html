1. Architecture & End-to-End Workflow

The MeterFlow platform decouples raw event telemetry from financial calculation and billing systems. It operates in four coordinated phases: Ingestion → Metering → Rating → Settlement.

+---------------------------------------------------------------------------------+ | API EVENT SOURCES | | [AI Token Inferences] [API Gateway Requests] [GPU Cloud Compute] | +---------------------------------------+-----------------------------------------+ | (HTTP POST /events or /events/batch) v +---------------------------------------------------------------------------------+ | 1. EDGE INGESTION & IDEMPOTENCY | | - Idempotency Deduplication Cache (LRU Hash Ring) -> Drops Duplicate Bills | | - Asynchronous Mongoose Persistence to MongoDB "events" collection | +---------------------------------------+-----------------------------------------+ | v +---------------------------------------------------------------------------------+ | 2. REAL-TIME METERING & AGGREGATION | | - In-Memory Sliding Window Aggregator (Zero-lock concurrent math) | | - Aggregations: SUM (Tokens), MAX (Storage), COUNT (Calls), UNIQUE (MAU) | | - Real-time Server-Sent Events (SSE) Broadcast to Next.js Web Console | +---------------------------------------+-----------------------------------------+ | v +---------------------------------------------------------------------------------+ | 3. PRICING & RATING ENGINE | | - Evaluates Rate Cards: Graduated Tiers, Volume Tiers, Packages, Free Credits | | - Real-time Accrued Cost calculation & Tenant Budget Limit Alarms (80% / 100%) | +---------------------------------------+-----------------------------------------+ | v +---------------------------------------------------------------------------------+ | 4. BILLING FEEDS & SETTLEMENT ENGINE | | - Automated Invoice Generator with Line Item Math Breakdown | | - Outbound Webhook Delivery: Stripe Usage Record API + NetSuite ERP (HMAC-SHA) | | - Executive Printable Invoice View (Receipt HTML/PDF) | +---------------------------------------------------------------------------------+

Core Architecture Components

⚡ Edge Ingestion Listener

Accepts single and batch telemetry payloads (up to 2,000/batch) with sub-millisecond overhead. Idempotency keys prevent double billing on network retries.

⏱️ Metering Aggregator

Maintains running totals per customer and meter. Supports mathematical formulas with filter expressions (e.g. model == 'claude-3-5-sonnet').

🧮 Pricing Engine

Calculates consumption bills using multi-tier rate cards. Subtracts free allowances and computes graduated tier brackets with exact currency precision.

📦 Outbound Billing Feeds

Generates finalized invoices and delivers signed HMAC-SHA256 payloads to Stripe Billing API and corporate ERP accounting systems.

2. Consumption Meters & Aggregation Rules

A Meter defines the exact logic of how raw API telemetry translates into billable usage units. MeterFlow supports 6 mathematical aggregation functions:

Aggregation Type Mathematical Logic Typical Use Case Example Properties
SUM ∑ (properties[valueProperty]) LLM Input/Output Tokens, Cloud Runtime Hours tokens: 2100, vCpuHours: 2.5
MAX Max(properties[valueProperty]) Peak High-Watermark Storage, Peak Concurrent DB Connections storageGb: 450.2, connections: 84
COUNT Count(matching events) API Invocations, OCR Scans, Webhook Deliveries units: 1, endpoint: "/v1/inference"
UNIQUE_COUNT Cardinality of Set(properties[valueProperty]) Monthly Active Users (MAU), Unique Devices, IP Addresses userId: "usr_9410", ip: "192.168.1.1"
WEIGHTED_AVG (∑ val × weight) / ∑ weight Average Latency, Server Cluster Load duration: 120ms, weight: 5
LATEST Last recorded state value Current Provisioned License Seats, Active Workers seatCount: 25

Pre-configured Enterprise Meters

1. LLM Generative Tokens (llm_tokens_total)

SUM(ai.completion.properties.tokens)

Tracks token consumption across prompt and completion inferences.

2. API Gateway Invocations (api_requests_total)

COUNT(api.request.properties.units)

Counts billable HTTP and gRPC gateway requests.

3. GPU & Cloud Compute Hours (gpu_compute_hours)

SUM(cloud.compute.properties.vCpuHours)

Dedicated GPU clusters (NVIDIA A100) and vCPU compute runtime.

4. Monthly Active Users (monthly_active_users)

UNIQUE_COUNT(user.session.properties.userId)

Deduplicated unique user identities active within the billing cycle.

Property Extraction & Filters: Meters support arbitrary filtering criteria. For example, a meter can track only events where properties.model === "claude-3-5-sonnet" or properties.region === "us-east-1".

3. Complex Pricing Models & Rate Cards

MeterFlow provides mathematically rigorous pricing engines supporting four distinct billing models with included free credit allowances.

1. Graduated Tiered Pricing (Marginal Brackets)

Usage is partitioned into tiers. Each tier applies its unit rate only to the consumption falling within its specific range.

Example Rate Card: LLM Generative Tokens (Free Allowance: 100,000 tokens) Tier 1: 0 - 500,000 tokens @ $0.0020 / token Tier 2: 500,001 - 2,500,000 tokens @ $0.0015 / token Tier 3: 2,500,001+ @ $0.0008 / token If Consumed Quantity = 1,200,000 tokens: 1. Free Allowance: 100,000 tokens included ($0.00) 2. Billable Units: 1,200,000 - 100,000 = 1,100,000 billable units 3. Tier 1 Brackets: First 500,000 @ $0.0020 = $1,000.00 4. Tier 2 Brackets: Remaining 600,000 @ $0.0015 = $900.00 ----------------------------------------------------------------------- Total Accrued Cost = $1,000.00 + $900.00 = $1,900.00

2. Comparison of Pricing Models

Model Behavior Formula
GRADUATED Marginal pricing per tier bracket Cost = ∑ (Units in Tier_i × Rate_i)
VOLUME Entire volume priced at single rate reached Cost = Total Units × Tier_Matched_Rate
PACKAGE Billed per block of units (rounded up) Cost = ⌈Total Units / PackageSize⌉ × PackagePrice
FLAT_FEE Flat pay-as-you-go rate per unit Cost = Total Units × UnitPrice
